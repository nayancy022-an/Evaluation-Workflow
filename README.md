# EvalFlow: Developer Evaluation Workflow

A full-stack recruiter dashboard that evaluates developer candidates from **GitHub activity, LeetCode performance and resume text**, then turns that evidence into transparent scores and a **recruitment potential heatmap** across roles.

**[Live demo(https://evaluation-workflow.onrender.com/))** · hosted on Render's free tier, so the first load can take up to a minute while the server wakes up.

## Features

- **Secure accounts:** register and sign in with email and password. Passwords are hashed with bcrypt and sessions use a JWT stored in an httpOnly cookie.
- **Private workspaces:** every recruiter only sees the candidates they evaluated.
- **Candidate intake:** target role, GitHub username, LeetCode stats and resume text (paste it or import a TXT, MD, CSV or JSON file).
- **Recruitment potential heatmap:** after you submit a candidate, the app shows the estimated chance of being recruited and a colour-coded role by signal grid (Resume fit, GitHub, LeetCode, Hire potential).
- **Explainable scoring:** overall fit, per-signal scores, matched role keywords, strengths, risks and a hiring recommendation.
- **Competency radar:** six competencies visualised on a radar chart.
- **GitHub enrichment:** the backend reads public profile and repository data, and falls back to a default profile if GitHub is unavailable or rate limited.
- **Candidate shortlist:** search, reopen, delete and export any evaluation as JSON.
- **Responsive UI:** built with Tailwind CSS and shadcn/ui.

## How scoring works

| Signal | Weight in overall fit | Based on |
| --- | --- | --- |
| Resume | 38% | role keyword match, leadership, testing, experience and clarity cues |
| GitHub | 34% | repositories, stars, followers, languages |
| LeetCode | 28% | problems solved and acceptance rate |

**Recruitment potential** is calculated for every supported role by scoring the resume against that role's keywords and combining it with the GitHub and LeetCode scores. The estimated chance of being recruited uses a logistic curve centred on a score of 60. Scores of 75 or more are rated **High**, 55 to 74 **Moderate**, and below 55 **Low**.

The hiring summary is **rule-based** (a transparent rubric), not generated by a language model. Scores are meant to support a recruiter's judgement, not replace it.

## Getting started

**Prerequisites:** Node.js 18 or newer and a MongoDB database (a free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster works).

```bash
git clone https://github.com/nayancy022-an/Evaluation-Workflow.git
cd Evaluation-Workflow
npm install
```

Create a `.env` file in the project root:

```env
MONGODB_URI=mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/evalflow?retryWrites=true&w=majority
JWT_SECRET=replace-with-a-long-random-string
PORT=3000
```

Generate a strong secret with:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Make sure your current IP address is allowed under **Network Access** in MongoDB Atlas.

### Run in development

```bash
npm run dev:full
```

Open `http://localhost:5173`. The Vite dev server proxies `/api` calls to the backend on port 3000. If `dev:full` does not work on your machine, run `npm run api` and `npm run dev` in two separate terminals.

### Run a production build

```bash
npm run build
npm start
```

Open `http://localhost:3000`.

## API

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/api/health` | Service and database status |
| `GET` | `/api/roles` | Supported roles and their keywords |
| `POST` | `/api/auth/register` | Create an account |
| `POST` | `/api/auth/login` | Sign in (rate limited) |
| `POST` | `/api/auth/logout` | Sign out |
| `GET` | `/api/auth/me` | Current user |
| `GET` | `/api/shortlist` | Your evaluated candidates |
| `POST` | `/api/evaluate` | Score a candidate and save the evaluation |
| `GET` | `/api/candidates/:id` | One saved evaluation |
| `DELETE` | `/api/candidates/:id` | Remove a candidate |
| `DELETE` | `/api/shortlist` | Clear your shortlist |

All routes except health, roles and the auth routes require a signed-in user.

## Deployment (Render)

1. Push the repository to GitHub.
2. In Render, create a **Web Service** from the repository.
3. Use these settings:
   - **Build command:** `npm install --include=dev && npm run build`
   - **Start command:** `npm start`
4. Add the environment variables `MONGODB_URI`, `JWT_SECRET` and `NODE_ENV=production`.
5. In MongoDB Atlas, allow Render to connect under **Network Access**.

## Security notes

- Passwords are hashed with bcrypt and are never stored in plain text.
- The session cookie is `httpOnly`, `SameSite=Lax`, and `Secure` in production.
- Login attempts are limited to 10 per 15 minutes per IP and email.
- Secrets live in environment variables and `.env` is excluded from version control.
- The login rate limiter is kept in memory, so it resets when the server restarts.
